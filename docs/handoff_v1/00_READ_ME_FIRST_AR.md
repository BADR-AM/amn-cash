# Wallet Manager / Wallet Receiver — Complete Coding Agent Handoff (v1.0)

## ما هذا الأرشيف؟
حزمة واحدة لتسليم **مواصفات المشروع + تصميم الواجهات + عقود النقل + أمثلة الحسابات + تعليمات الوكيل** لمطور أو وكيل برمجة (Codex / Claude Code / غيرهما). **لا تتضمن سورس كود المشروع الأصلي SMSGate، ولا APK أو EXE نهائي.** يجب جلب المصدر الأصلي قانونيًا أثناء EPIC 0.

## الهدف
تطبيق Android Native (APK) يستقبل إشعارات مالية محددة من شريحة Vodafone Cash، يصفي الرسائل الحساسة داخل الهاتف، ويزامن الأحداث عبر اتصال آمن مع Windows Receiver Service؛ وبرنامج Windows Native (WPF .exe) يعرض المعاملات والفترات ويحسب رسوم الخدمات والتكاليف والأرباح والتقارير والمراجعة.

## ابدأ من هنا بالترتيب
1. اقرأ `AGENTS.md` (قواعد الوكيل الملزمة).
2. اقرأ `docs/architecture/technical_blueprint.md` ثم `docs/uiux/UI_UX_Specification.md`.
3. اقرأ `docs/implementation/ROADMAP.md` ثم `docs/implementation/ACCEPTANCE_CHECKLIST.md`.
4. اطّلع على `design/wireframes_interactive.html` (Prototype تجريبي، افتحه محليًا) ولقطات الشاشة في `design/wireframes/`.
5. استخدم `protocol/openapi.yaml` و`protocol/event-envelope.schema.json` كمسودتين تعاقديتين تحتاجان اعتمادًا واختبارات توافق قبل الإنتاج.
6. شغّل `python -m unittest discover -s tests -v` للتحقق من أمثلة محرك الرسوم المرجعي. الشيفرة المرجعية **ليست** implementation إنتاجيًا.
7. ابدأ **EPIC 0: Fork / Audit / Real Device SMS proof** قبل تنفيذ باقي المزايا.

## قرارات V1 المثبتة
- Windows: C# / .NET + WPF / MVVM؛ استقبال خلفي مستقل Windows Service؛ SQLite.
- Android: Kotlin + Jetpack Compose؛ استخراج مكونات مختارة من `capcom6/android-sms-gateway` بعد Fork وتدقيق الترخيص والإصدار والبناء.
- يبدأ الاتصال من Android إلى Windows عبر HTTPS موثّق ومقترن بكود QR.
- شاشة رئيسية عربية RTL بكروت كبيرة، شاشة معاملات، حاسبة رسوم، تقارير بنطاق تاريخ، مراجعة، أجهزة، إعدادات.
- قاعدة السعر الافتراضية **50 جنيه رسوم خدمة لكل 1000**، **10 جنيه تكلفة تقديرية لكل 1000**، **40 جنيه صافي ربح تقديري لكل 1000**؛ كل القيم قابلة للتغيير وتؤرشف بإصدار.
- هذه قاعدة داخلية مُدخلة للمستخدم، **ليست تعريفة رسمية مؤكدة من Vodafone**؛ ولا تُطبّق تلقائيًا على كل تحويل SMS وارد، بل على عمليات خدمة سحب مصنفة ومؤهلة.
- رسالة SMS المرصودة ليست إثباتًا نهائيًا لوصول الأموال؛ التحقق المالي يحتاج مطابقة مستقلة أو مراجعة موثقة مخوّلة.
- لا يجوز إرسال أو حفظ PIN/OTP في النظام أو سجلاته. لا فتح API للعامة بدون حماية أو تعطيل TLS.

## توجيه عملي لكودكس
نقطة البداية: `AGENTS.md` ثم `docs/implementation/ROADMAP.md`. قدّم سجل تدقيق بناء المصدر الأصلي، قائمة تبعيات، خطة اختبار هاتف فعلي، وعقد بروتوكول مثبت في اختبارات؛ بعد ذلك اكتب الكود خطوة بخطوة، مع تنفيذ اختبارات قبل الادعاء بالجاهزية.

## ما هو موجود؟
- `docs/architecture/technical_blueprint.md`: التفصيل الهندسي، إدارة الأحداث، الأمان، البيانات والرسوم.
- `docs/uiux/UI_UX_Specification.md`: كل شاشة وحالتها ومسار تفاعلها.
- `design/wireframes_interactive.html`: Prototype واجهات تجريبي.
- `design/wireframes/`: أربع لقطات UI مرجعية.
- `design/concepts/`: تصورات مرئية تاريخية **لا تستخدم الشعارات الرسمية منها داخل المنتج النهائي**.
- `protocol/`: OpenAPI وJSON Schema وبيانات synthetic.
- `finance/`: سياسة حساب الرسوم وأمثلة مضبوطة.
- `tests/`: مرجع واختبارات حساب حتمية.
- `docs/implementation/`: ترتيب العمل وDefinition of Done وأمن الإنتاج.
- `sources/`: كيفية استيراد وتدقيق SMSGate والترخيص.

## تنبيه حول نشر التطبيق
النسخة المستهدفة APK خاصة (sideloaded)، لكن صلاحيات SMS قد تكون محكومة بسياسات جهاز Android ومصدر التثبيت وإصداره. **اختبار استقبال SMS على الهاتف المستهدف Gate ملزم** قبل تنفيذ المشروع بالكامل. يظل إثبات التشغيل الدائم والإنتاجي مشروطًا بالاختبارات الأمنية والتجريبية.
